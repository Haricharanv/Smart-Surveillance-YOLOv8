📚 Day 1: Core Concepts

Grayscale Representation

Converting BGR to Grayscale isolates luminance from chrominance, simplifying operations and reducing compute bandwidth by 66% (1 channel instead of 3).

CLAHE Equalization

Contrast Limited Adaptive Histogram Equalization operates on local 8x8 tiles. It limits contrast amplification using a clip limit to prevent over-amplifying background camera noise.

Thermal Colormapping

Uses lookup tables (e.g. Inferno) to convert grayscale light intensities into multi-color heat spectrum visualizations, enhancing target distinguishability.

Multi-Sensor Edge Fusion

Detects sharp structural profiles via Canny edge filters and overlays them back onto thermal streams using weighted addition to restore structural boundaries.

def enhance_low_light(frame, colormap_idx=0, enable_edge_fusion=True):
    gray = cv2.cvtColor(frame, cv2.COLOR_BGR2GRAY)
    clahe = cv2.createCLAHE(clipLimit=CLAHE_CLIP_LIMIT, tileGridSize=CLAHE_GRID_SIZE)
    enhanced = clahe.apply(gray)
    
    _, colormap_code = COLORMAPS[colormap_idx]
    thermal = cv2.applyColorMap(enhanced, colormap_code)
    
    if enable_edge_fusion:
        edges = cv2.Canny(enhanced, 40, 120)
        edges_colored = cv2.cvtColor(edges, cv2.COLOR_GRAY2BGR)
        edges_colored = np.where(edges_colored > 0, [255, 255, 0], 0).astype(np.uint8)
        fusion = cv2.addWeighted(thermal, 0.82, edges_colored, 0.18, 0)
        return fusion
    return thermal

💬 Interview Q&A (Interactive)

Why use CLAHE instead of standard global histogram equalization?
Answer: Global histogram equalization applies a single transformation function to the entire image. If the image has extremely dark areas and extremely bright areas, global equalization will over-saturate the highlights and amplify background noise in the dark areas. CLAHE (Contrast Limited Adaptive Histogram Equalization) solves this by dividing the image into localized tiles (usually 8x8) and equalizing them independently. Crucially, it clips the histogram height at a specified limit to prevent contrast over-amplification, redistributing the clipped bins across the histogram before calculating the transformation mapping.
What is the role of multi-sensor fusion in surveillance systems?
Answer: Multi-sensor fusion combines complementary inputs from different spectrum sensors—such as thermal infrared (sensitive to body heat) and electro-optic visible light (sensitive to structural textures and colors)—into a unified visual stream. This allows a security operator or downstream AI models to detect thermal targets while retaining critical details like physical edges, distance contours, and structural environments that thermal-only cameras fail to resolve.

📚 Day 2: Core Concepts

Decoupled Detection Heads

YOLOv8 uses a decoupled head architecture where classification scores and bounding box coordinates are predicted by separate specialized branches, boosting accuracy.

Anchor-Free Bbox Regression

Predicts target box centers and boundaries directly rather than offset scaling relative to pre-configured anchor boxes, making the network simpler and faster.

Temporal Tracking Association

Maintains target identities over time by linking detections across frames using Kalman filter motion predictions and spatial overlap calculations.

ByteTrack Logic

Rather than discarding low-confidence bounding boxes (which often represent occluded or low-contrast targets), ByteTrack keeps them and maps them to active tracks using IoU association.

💬 Interview Q&A (Interactive)

What makes YOLOv8 different from previous anchor-based architectures?
Answer: YOLOv8 is anchor-free, meaning it directly predicts the center coordinates and dimensions of objects rather than estimating offsets relative to a grid of predefined anchor boxes (anchors). This eliminates the complex anchor hyperparameter tuning step. It also features a decoupled head where bounding box regression and classification are split into separate convolutional paths, which avoids conflicts between class learning and spatial boundary regression.
How does ByteTrack prevent tracking losses during occlusions?
Answer: Standard trackers discard any bounding box with a confidence score below a threshold (e.g., 0.5), which leads to identity loss (ID switches) if an object gets temporarily covered or enters low-contrast shadow. ByteTrack preserves all detections, separating them into high-confidence and low-confidence pools. It first matches high-confidence boxes to existing tracks. For remaining unmatched tracks, it performs a second matching step against the low-confidence pool. This recovers occluded targets since their overlap with predicted Kalman filter tracks remains high even if their detection score has dropped.

📚 Day 3: Core Concepts

Intersection over Union (IoU)

A metric measuring the overlap area divided by the union area of predicted vs ground-truth bounding boxes, evaluating spatial accuracy.

Precision / Recall Trade-off

Precision measures the ratio of true detections to all predicted detections (low false alarms). Recall measures the ratio of true detections to all actual objects (low missed detections).

MOTA (Overall Tracking Accuracy)

Summarizes tracking performance across frames by penalizing False Positives (FP), False Negatives (FN), and Identity Switches (IDSW).

IDF1 (ID Consistency Metric)

Focuses on tracking identity consistency over long durations, measuring how long a specific track preserves the correct target ID.

🔍 Code Reference

📄 evaluate_metrics.py (Line 11-34)
def calculate_iou(boxA, boxB):
    xA = max(boxA[0], boxB[0])
    yA = max(boxA[1], boxB[1])
    xB = min(boxA[2], boxB[2])
    yB = min(boxA[3], boxB[3])

    interArea = max(0, xB - xA + 1) * max(0, yB - yA + 1)
    boxAArea = (boxA[2] - boxA[0] + 1) * (boxA[3] - boxA[1] + 1)
    boxBArea = (boxB[2] - boxB[0] + 1) * (boxB[3] - boxB[1] + 1)

    unionArea = float(boxAArea + boxBArea - interArea)
    return interArea / unionArea if unionArea > 0 else 0.0

💬 Interview Q&A (Interactive)

Explain the difference between MOTA and IDF1.
Answer:
  • MOTA (Multiple Object Tracking Accuracy) focuses primarily on local detection performance and tracking configuration. It aggregates False Negatives, False Positives, and local ID switches frame-by-frame. It is highly sensitive to detection quality but can be skewed if a tracker switches IDs frequently but recovers detection immediately.
  • IDF1 (ID F1-Score) evaluates long-term association consistency. It measures the F1-Score of correctly identified trajectories across the entire video. IDF1 is crucial for multi-camera tracking or target re-identification where keeping a continuous identity mapping over time is more important than local box jitter.
How do you mathematically compute the F1-Score?
Answer: The F1-Score is the harmonic mean of Precision and Recall. The mathematical formula is:

F1 = 2 * (Precision * Recall) / (Precision + Recall)
Where:
  • Precision = $TP / (TP + FP)$
  • Recall = $TP / (TP + FN)$
We use the harmonic mean instead of the arithmetic mean because it heavily penalizes extreme values (e.g., if Precision is 100% and Recall is 0%, the arithmetic mean is 50%, but the F1-score is 0%, correctly identifying the failure).

📚 Day 4: Core Concepts

ONNX Compilation

Compiles PyTorch model graphs into standard static layers, optimizing compute operator calls and removing Python runtime overhead.

Inference Optimization Engines

Formats like ONNX can be deployed directly via highly optimized local engines such as TensorRT (NVIDIA), OpenVINO (Intel), or ONNX Runtime.

OpenVINO (Intel) Engine

Specialized compiler that quantizes model weights and schedules parallel threads to maximize inference throughput on Intel CPU/GPU architectures.

C++ OpenCV DNN APIs

Allows loading ONNX model weights directly in C++ via `cv::dnn::readNetFromONNX`, preprocessing images, and running network forward passes without deep learning framework dependencies.

💬 Interview Q&A (Interactive)

What happens during OpenCV's dnn::blobFromImage operation?
Answer: `cv::dnn::blobFromImage` converts an input image into a 4D tensor (blob) formatted for neural network layers (typically batch, channels, height, width - NCHW). Under the hood, it performs:
  1. Resizing: Scales the image height and width to target network dimensions (e.g. 640x640).
  2. Normalization: Scales pixel values (e.g. multiplying by 1/255.0 to map RGB colors from 0-255 to 0.0-1.0).
  3. Channel Swapping: Swaps red and blue channels (BGR to RGB) because OpenCV loads images as BGR, while SOTA deep learning networks expect RGB.
  4. Mean Subtraction: (Optional) Subtracts average dataset pixel values to center the dataset distribution.
How is the output tensor shape of YOLOv8 structured, and how do we parse it in C++?
Answer: The raw output of YOLOv8 is a tensor of shape `[1, 84, 8400]`.
  • 1: Batch size.
  • 84: 4 bounding box coordinates (center-x, center-y, width, height) + 80 class confidence scores.
  • 8400: Number of candidate boxes/anchors.
To parse this in C++, we flatten the batch dimension to get a `[84, 8400]` matrix and transpose it to `[8400, 84]` for easier row-by-row iteration. For each of the 8400 candidates:
  1. We read the class confidence score (for target class 'person', index 4).
  2. If the score exceeds our threshold, we extract the bounding box center coordinates `[0, 1]` and sizes `[2, 3]`.
  3. We convert center coordinates to top-left corner coordinates: `left = cx - 0.5 * w`, `top = cy - 0.5 * h`.
  4. We scale coordinate values back to the original image dimensions using scale factors.
  5. Finally, we run the coordinates through `cv::dnn::NMSBoxes` to perform Non-Maximum Suppression and remove overlapping boxes.
